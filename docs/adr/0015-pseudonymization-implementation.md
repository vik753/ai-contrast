# ADR 0015 — Pseudonymization: implementation in stage 5b

- Status: accepted (2026-10-29, stage 5b merged; proposed by the tech lead on 2026-10-28, `security-reviewer` approved the design after round 2)
- Date: 2026-10-28
- Related: ADR 0008 (design — this ADR only fixes the interfaces), ADR 0009 (Layers 1–2), ADR 0013 (no mapping in storage), ADR 0014 (segmentation), threat model T3, T5, T11

## Context

ADR 0008 defines what is masked, the pipeline, the type gate and the tests. Stage 5b builds it. Stages 6 and 9 add the AI provider and the analysis endpoint; they must find the gate, the safety pass and the canary harness ready.

## Decision

1. **Detection is part of `/api/segment`** (ADR 0014 point 1). The same child process segments and then detects, so all text passes one server path. The reply gets new fields:
   - `detector_version` (string; changes whenever rules or tables change);
   - `entities`: `[{ "id": "e1", "class": "ORG", "precision": "high" | "normal", "spans": [[block, start, end], …] }]` — one entity per distinct value in the document (case forms, initials and transliterations of the same name grouped by the detector); spans point into the returned cleaned blocks; **no value strings** in the reply (the browser reads them from the spans);
   - `requisites`: `[{ "clause": "c41", "lines": [{ "span": [block, start, end], "action": "drop" | "keep" }] }]`; a kept line adds the clause warning `requisites_condition`;
   - `neutralized`: spans of placeholder look-alikes in the source (`[ORG_2]`, `[A.PERSON_1]`, also matched on the confusable skeleton), each also a clause warning `placeholder_lookalike`. **`/api/segment` neutralizes them in the returned cleaned blocks** (the square brackets become `⟦ ⟧`; same length, so spans stay valid) and the preview shows each one; so no source text can ever equal a placeholder, and the restore step never puts a real name into attacker text;
   - clause warnings `masked_next_to_amount`.
   Caps: at most 5,000 entities and 50,000 spans per file, **checked while detection runs** (not after); above → `422 too_many_identifiers` (fail closed). Running clauses and headings are detected and masked like any text; nothing outside the requisites rule is ever dropped. Headings reach the AI only inside safety-passed clause text.
2. **Detector** (`app/pseudo/`): pure functions, linear-time patterns, tables checked into the repository (legal forms, context keywords, role words, obligation markers, requisites labels, UK/RU name-ending rules); checksum validators for ЄДРПОУ, РНОКПП, IBAN (ISO 13616) and cards (Luhn); matching on a de-hyphenated, NFKC + confusable-skeleton view with an offset map back to the cleaned text (ADR 0009: NFKC only for matching). When one source character expands to several view characters, a match boundary inside it is snapped outward to the whole source character (property test). Grouping of forms (stems, initials, transliteration) uses a hashed stem index — linear, never pairwise comparison. No ML, no new runtime dependency; the confusable table (UTS #39 subset for Latin/Cyrillic/Greek/digits) is generated and checked in like the Layer 1 table.
3. **Browser preview** (`frontend/src/pseudo/`): the client sees every entity and requisites decision; can mask more text (select a range → choose a class) and unmask `normal` entities; `high` entities cannot be unmasked. Placeholders are assigned in the browser in first-occurrence order per document and class: `[A.ORG_1]`. The browser builds the masked clauses and the mapping; both live only in memory (ADR 0013 point 9a), are dropped with the contract, and the mapping is never in any request.
4. **Safety check endpoint** `POST /api/safety-check` (stateless): input `UntrustedMaskedDocument` = `{ "label": "A", "detector_version": "…", "clauses": [{ "id": "c1", "text": "…masked…" }], "acknowledged_unmasked": [["c3", 10, 18], …] }`. Grammar: label `[A-Z]`; clause id `c[1-9][0-9]{0,3}`; placeholder `[<label>.<CLASS>_<n>]` with a known class and `n` from 1 to 5000 without a leading zero, numbered per class from 1 with no gaps. Caps for masked input: the clause cap of ADR 0014 plus room for placeholders (40,000 characters per clause, 2,000,000 per document). Runs in the sandbox like `/api/segment` (same slot, limits and body rules). Checks in order: version (`409 detector_version_mismatch`), Layer 1 idempotence (`422 input_not_clean`), placeholder syntax on the text **and on its confusable skeleton** (`422 invalid_placeholder`), then **the whole detector re-runs** on the masked text (placeholders skipped; the requisites context is unknown here, so checksummed codes count as high precision): every hit must be inside a placeholder or listed in `acknowledged_unmasked` (the `normal` entities the client unmasked in the preview); otherwise `422 unmasked_identifier` with `{ "spans": [[clause_id, start, end], …] }` (offsets only, never values). Acknowledged spans that hit a `high` rule are refused the same way. Each acknowledged span must equal one detector hit span exactly; the list is sorted, without overlaps, at most 50,000 entries — anything else is `422 invalid_request`. A `normal` detector hit fully contained in an acknowledged span (for example the person inside an unmasked signature) counts as acknowledged; a `high` hit inside stays refused. Placeholder grammar is checked on the literal `[` only (a neutralized `⟦…⟧` is ordinary text). Stage 10 rule: the browser never restores names in model free text at a position that matches a neutralized span, nor in a token whose brackets differ from `[`/`]`. Success → `200 { "ok": true, "detector_version": "…", "digest": "<sha256 of the canonical masked document>" }`. Stage 9's analysis endpoint runs the same `safety_pass()` again on its own input; the digest is informational only (not a token).
5. **Type gate** (`app/pseudo/gate.py`): `PseudonymizedDocument`, `PseudonymizedClause`, `PseudonymizedText`, `ConfirmedTopic` — frozen dataclasses with slots; the sentinel is an `InitVar` with no default, checked in `__post_init__`; fields are immutable (strings, tuples of frozen gate objects, enums — no lists or dicts); `__copy__`, `__deepcopy__`, `__reduce__` and `__reduce_ex__` raise, so `copy`, `pickle` and `dataclasses.replace` cannot make one. Only `safety_pass()` (and, for topics, `confirm_topic()` in stage 7) create them. An AST policy test enforces ADR 0008 point 3 from now on: outside `gate.py` no constructor call, `cast`, `__new__`, `object.__setattr__`, `dataclasses.replace`, `copy.copy`/`deepcopy`, `pickle` on gate types or sentinel use; every module under `app/ai/` (by glob, as soon as it exists) may take only gate types, enums and constants.
6. **Canary harness** (`backend/tests/canary/`): a reusable fixture that plants canary identifiers of every class and location, runs the whole pipeline (extract → segment/detect → browser-equivalent masking in Python → safety check) and asserts no canary in the masked document, logs, error bodies or responses other than `/api/segment` (which must return the original text to the browser). Stage 6 plugs the `AIProvider` wire capture into the same harness. Matching: case-insensitive, NFKC, confusable skeleton, separators removed.
7. **Detector eval** (`backend/eval/pseudo/`): recall and precision **per class and per language** on the S5b-T0 corpus; a partially masked value counts as a miss. Gates for merge: recall 1.0 for high-precision classes with context; recall ≥ 0.95 for every other class in every language; precision ≥ 0.85 per language. A **held-out split** (about a third of the size of the main corpus, written by `domain-analyst` after the detector exists, in `backend/eval/pseudo/heldout/`; developer tasks must not read that folder; it runs in CI and for `ai-eval-engineer`) guards against overfitting. A committed baseline file holds the numbers; a drop fails CI.

## Consequences

- Positive: one server path for text; the browser never sends the mapping; stage 6/9 reuse the gate, safety pass and canary harness.
- Negative: `/api/segment` replies grow (entities and spans). The 4 MiB result cap still applies; the size test at the caps is extended.
- Residual risk (ADR 0008): detection is never complete; the mandatory preview is the final control. The server re-check sees only the masked text: a later occurrence found only by stem matching to a preamble definition (not by a rule on its own) cannot be re-found by the server if the browser left it unmasked; the canary harness tests this path.
